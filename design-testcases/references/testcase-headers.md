# 标准测试用例表头定义（合并版）

本文件定义测试用例 Excel 输出的标准列结构，共 **30 列**。
在原 API 测试 25 列基础上增加：用例编号、关联原子能力、是否自动化、自动化断言方式、风险与待确认。

## 标准列定义

| 列号 | 列名 | 英文Key | 必填 | 取值说明 |
|------|------|---------|------|---------|
| A | 用例编号 | case_id | ✅ | 格式 `TC-{模块缩写}-{三位序号}`，如 `TC-ADDR-001`，编号不复用 |
| B | 关联原子能力 | ac | ✅ | 关联 `AC-{编号}`，无则填 `未关联`，覆盖矩阵据此生成 |
| C | 系统/项目 | project | 可选 | 所属系统或项目名称 |
| D | 模块 | module | ✅ | API 所属业务模块，如"地址管理" |
| E | 功能 | feature | ✅ | 具体功能点，如"地址搜索" |
| F | 测试项 | test_item | ✅ | 本条用例的测试维度/场景描述 |
| G | 用例标题 | title | ✅ | `{动作}+{条件}+{预期结果}`，简明动词短语 |
| H | 前置条件 | preconditions | ✅ | 环境、数据、登录态、依赖服务 |
| I | 涉及到数据库表 | db_tables | 可选 | 如 `lsp_dev.lsp_address_suburb` |
| J | 测试数据 | test_data | ✅ | 入参 JSON（完整 Request Body 或 Query Params） |
| K | 测试步骤 | steps | ✅ | 按序编号，每步可操作 |
| L | 预期结果 | expected_result | ✅ | HTTP 状态码 + 响应字段 + 业务含义 |
| M | 验证SQL | validation_sql | ✅ | SELECT 语句验证 DB 变更，只读接口填 `N/A（只读接口）` |
| N | 实际结果 | actual_result | — | 执行阶段填写 |
| O | 是否通过 | is_passed | — | 执行阶段填写 |
| P | 预计工时(h) | estimated_hours | 可选 | 如 0.5 |
| Q | 执行时间(年月日) | execute_date | — | 执行阶段填写 |
| R | 测试进度(%) | test_progress | — | 执行阶段填写 |
| S | 用例类型 | case_type | ✅ | 固定值：`API测试` |
| T | 用例优先级 | priority | ✅ | 枚举：P0 / P1 / P2 / P3 |
| U | 是否回归用例 | is_regression | ✅ | 是 / 否 |
| V | 是否阻塞上线 | is_blocker | ✅ | 是 / 否 |
| W | 关联需求ID | requirement_id | 可选 | 需求文档 ID |
| X | API URL | api_url | ✅ | `{METHOD} {path}`，如 `POST /address/search` |
| Y | BUG数 | bug_count | — | 默认 0 |
| Z | BUG未解决数 | bug_unresolved | — | 默认 0 |
| AA | 用例版本 | case_version | ✅ | 从 1 开始 |
| AB | 是否自动化 | automatable | ✅ | 是 / 否 / 部分 |
| AC | 自动化断言方式 | assertion_method | 可选 | 接口返回 / 数据库字段 / 日志 / 事件 / 页面元素 |
| AD | 风险与待确认 | risk | ✅ | 无则写"无"，拿不准的标【待确认】 |

> **注意**：`test_type`（正向/负向/边界/安全/权限）为内部字段，用于控制 Excel 行背景色，**不作为列导出**。

## 优先级标准

| 优先级 | 含义 | 判定规则 |
|--------|------|---------|
| P0 | 冒烟级 | 主流程正向、阻断级异常（如登录失败、核心接口 500）；每个 AC 至少 1 条 P0 |
| P1 | 核心用例 | 主要业务流程、关键负向（必填缺失、类型错误、唯一冲突） |
| P2 | 增强覆盖 | 次要场景、大多数边界用例（长度 N±1、枚举非法值） |
| P3 | 边缘用例 | 极端边界、安全注入、罕见异常、并发/幂等低概率场景 |

## 自动化可行性判定

| 结论 | 判定条件 |
|------|---------|
| 是 | 接口可调用、断言可程序化、数据可构造 |
| 部分 | 主流程可自动化，部分校验需人工确认（如图文识别、第三方回调） |
| 否 | 依赖人工审核、第三方未开放能力、物理设备 |

## 用例类型（test_type）说明

| 类型 | 含义 | 最低比例 |
|------|------|---------|
| 正向 | 合法入参，期望成功响应 | ≥ 40% |
| 负向 | 非法/缺失入参，期望错误响应 | ≥ 30% |
| 边界 | 参数边界值（min/max/null） | ≥ 20% |
| 安全 | SQL注入/XSS/越权等安全场景 | ≥ 10% |
| 权限 | 认证/授权/数据权限场景 | 按需 |

## 验证 SQL 规范

验证 SQL 必须满足：
1. 仅使用 `SELECT`，不包含 DML（禁止 INSERT/UPDATE/DELETE）
2. 包含 `WHERE` 条件，精确定位测试产生的数据
3. 注释说明检查目的：`-- 验证搜索结果包含关键字`
4. 若操作不涉及数据写入（如纯查询接口），填写 `N/A（只读接口）`

**示例：**
```sql
-- 验证地址搜索返回包含关键字的记录
SELECT COUNT(*) FROM lsp_address_suburb
WHERE suburb_name LIKE '%上海%' OR district LIKE '%上海%';
```

## Excel 样式规范

| 元素 | 样式 |
|------|------|
| 表头行 | 背景：#2E75B6（蓝）；字色：白；加粗；居中 |
| P0 用例行 | 背景：#FFC7CE（浅红），优先级最高 |
| 正向用例行（test_type=正向） | 背景：#FFFFFF（白） |
| 负向用例行（test_type=负向） | 背景：#FFF2CC（浅黄） |
| 边界用例行（test_type=边界） | 背景：#DDEEFF（浅蓝） |
| 安全用例行（test_type=安全） | 背景：#FFE4CC（浅橙） |
| 权限用例行（test_type=权限） | 背景：#F2F2F2（浅灰） |
| 自动换行 | F/G/I/J/K/L/M/AD 列开启 |
| Sheet | 用例明细 / 覆盖矩阵 / 待确认清单 / 覆盖率统计 |
